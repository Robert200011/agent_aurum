# 阶段六 P6.4 验收报告：备份、恢复与数据保留

> 验收日期：2026-08-02  
> 范围：单机开发 Compose 基线  
> 默认目标：RPO 24 小时、RTO 4 小时

## 1. 交付结果

- `scripts/phase6_backup.py` 与 PowerShell 包装器实现 PostgreSQL + MinIO 全版本加密备份、
  密文校验、独立副本接口、30 天保留和恢复目标防覆盖；
- MinIO bucket 初始化时开启版本控制，备份清单覆盖对象版本、删除标记与 SHA-256；
- 恢复自动校验 Alembic、表计数、RLS、财务汇总、引用、聊天关联、checkpoint 解密和对象；
- `deploy/retention-policy.json` 定义聊天、审计、检索日志、Trace、指标、日志和备份周期；
- 数据库保留执行器默认 preview，仅对白名单表执行，并在 apply 时写入审计日志；
- 备份成功指标与 `AurumBackupOverdue` 缺失/逾期告警形成最小失败告警闭环。

## 2. 本地恢复演练

使用系统 CSPRNG 临时生成专用 256 位密钥，未把密钥写入仓库、日志或报告。备份同时写入
primary 和 replica 目录，再恢复到全新的隔离目标：

- 数据库：`aurum_restore_p64_20260802`；
- bucket：`aurum-restore-p64-20260802`；
- 备份密文约 1.06 MB，恢复后当前对象 5 个；
- 演练 RPO：0.96 秒；演练 RTO：12.21 秒；
- Alembic、关键表计数、RLS、财务汇总、引用打开、聊天完整性、checkpoint 解密、对象哈希
  和数据库—原始对象键/哈希均为通过；恢复目标没有覆盖现有 `aurum` 数据库或
  `aurum-knowledge` bucket。开发数据库中的 `integration/` 测试夹具引用不作为生产对象，
  正式环境遇到该命名空间会 fail-closed；缺少的解析文本是可从原始文档重建的派生缓存。

机器报告保存在本机忽略目录 `.test-results/p6.4/restore-drill-final.json`。临时密钥在命令退出后
销毁，因此演练密文仅用于证明本次流程，不作为长期生产备份。正式备份必须使用外部密钥
系统中的持久密钥与真正异地副本。
