# 阶段六 P6.5 验收报告：生产部署、灰度发布与回滚

> 验收日期：2026-08-02  
> 范围：单机生产部署资产、CI 门禁、蓝绿发布和回滚演练；不包含真实公网服务器上线

## 1. 交付结果

- 生产 Compose 提供蓝/绿 API 与 Web、Gateway、Worker/Beat、PostgreSQL、Redis、MinIO 和完整观测栈；
- Caddy 仅作为公网入口，阻断 API 文档、内部运维接口和 `/metrics`，并保留 SSE 流式转发与排空窗口；
- API/Web 镜像写入 OCI 构建元数据，生产发布拒绝脏工作树、`latest` 和缺少备份证据的清单；
- 发布清单固定 Git、镜像、迁移、Graph、Prompt、评测数据集、配置、备份和操作人；
- 发布脚本自动执行备份、一次性迁移、候选健康检查、阶段六门禁、切流、观测和失败回滚；
- 回滚采用原子 Gateway 配置替换，不执行破坏性数据库降级；
- GitHub Actions 增加 Ruff、Mypy、Pytest、Alembic、前端检查、阶段六门禁、依赖审计、SBOM 和 Trivy 扫描。

## 2. 蓝绿与故障演练

本地独立生产栈使用发布 ID `p6.5-rehearsal-20260802T233427`。发布前加密备份、MinIO
版本化初始化、迁移、候选就绪和 P6.3 统一门禁均通过。

| 检查 | 结果 |
| --- | --- |
| 绿槽 HTTP 观测 | 20/20 为 200，错误率 0，槽位错误 0 |
| 绿槽延迟 | P50 30.85ms，P95 43.56ms |
| Prometheus 发布指标 | API 5xx 0、模型错误 0、队列 0、连接池比例 0 |
| 阈值决策 | 7/7 检查通过，候选被接受 |
| 故障注入 | 主动停止 `api-green` |
| 蓝槽回滚 | 10/10 为 200，错误率 0，槽位错误 0，P95 42.26ms |
| 自动回滚注入 | 切流后令 Prometheus 连接失败，发布返回非零并自动恢复蓝槽 10/10 |

回滚后的活动槽为蓝槽，证明旧槽在候选不可用或发布观测链路异常时仍可独立服务。演练生成的
证据位于忽略提交的 `.test-results/p6.5/`，生产运行时应转存到受控审计介质。

## 3. 暴露面验证

演练环境只有 Gateway 对外入口；PostgreSQL、MinIO API 和 Prometheus 仅绑定回环维护端口，
Redis、API、Web、Grafana 和 MinIO Console 均没有宿主机端口。Gateway 健康请求包含安全响应头
和 `X-Aurum-Release-Slot`，内部文档、指标及运维路径返回 404。

MinIO 内部链路启用 TLS 和显式 CA 信任，对象下载使用独立 Gateway 域名，避免路径前缀破坏
S3 签名。验收实际写入探针对象并经预签名 URL 下载，HTTP 200 且内容 SHA-256 一致。

## 4. 验收结论与边界

P6.5 的工程开发与本地蓝绿/回滚验收完成。该结果交付的是“可部署、可审计、可回滚”的生产
资产，不表示已经把系统发布到公网服务器。正式上线仍需由运维提供域名、证书、镜像仓库、
外部密钥、独立备份介质和人工切流批准，并在候选环境补做真实 Provider 冒烟和目标容量负载。
